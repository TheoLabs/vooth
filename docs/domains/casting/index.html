Composition · 구성·재생

Casting · 캐스팅(성우 버전)

캐릭터에 성우를 배정한 단위. 멀티버전 보이스툰에서 하나의 캐릭터에 붙는 성우 후보 = 버전이다. Character 1:N Casting → Creator. 음성(Recording)의 버전 좌표이자, 검수(회차×성우)·발행의 단위.

설계 admins/characters/:characterId/castings 멀티버전 Character ↔ Creator
구현 상태 = 설계. Casting은 아직 core-api 모듈로 존재하지 않는다. 본 문서는 합의된 필드·정책 기준이며, 상위 구성·재생 모델은 Playback, 부모는 Character 참고.

01 책임과 특성

  • 버전 = 캐스팅 — 멀티버전(시청자 선택)에서 한 캐릭터의 "성우 A판/B판"이 각각 Casting 한 건. (characterId, creatorId)로 유일.
  • 승자 채택 없음 — 오디션처럼 1명으로 수렴하지 않는다. 검수 통과한 모든 Casting이 발행(isPublished)되어 시청자가 캐릭터별로 고른다.
  • Recording의 버전 좌표 — 음성은 Recording(Line × Casting). 같은 대사라도 Casting마다 다른 음성·길이를 가진다(타임라인 버전별 해석의 입력).
  • 검수 단위 — EpisodeReview(회차 × 성우)의 "성우"가 곧 이 Casting. 버전별로 검수되고 통과 시 라이브.

02 애그리게이트 — Casting

공통 베이스 DddAggregate(id, createdAt/updatedAt/deletedAt, 이벤트)는 생략.

필드타입null설명
characterIdnumber✗대상 캐릭터(Character 1:N Casting). 논리 FK + INDEX
creatorIdnumber✗성우(Creator). 논리 FK + INDEX
isPublishedboolean✗이 버전이 라이브인지(시청자 선택 대상). 기본 false → 검수 승인 시 true (§03)
유일성. (characterId, creatorId)는 중복 불가(한 캐릭터에 같은 성우 두 번 배정 안 함). Character와 동일하게 앱 레벨 검사로 두되, 엄격히 가면 DB unique로 승격.

03 isPublished — 발행 토글

  • 기본 false — 캐스팅을 만들어도 바로 공개되지 않는다(녹음·검수 전).
  • 검수 승인 시 true — 해당 버전(회차×성우)의 EpisodeReview가 통과하면 라이브로 전환(이벤트 연동, 추후). MVP에선 관리자 수동 토글로 대체 가능.
  • 비공개 전환 — 문제 버전은 false로 내려 시청자 노출에서 제외(데이터·녹음은 보존).
  • 재생 선택 — 시청자는 캐릭터별 isPublished 버전 중 고른다(런타임 매핑; 사전 묶음이 필요하면 후속 CastSet).

04 라이프사이클 · 삭제

  • 생성(캐스팅 지정) — back-office가 캐릭터에 성우를 배정. character·creator 존재 검증 + (characterId, creatorId) 중복 거부.
  • 발행/비공개 — isPublished 토글(§03).
  • 해제(삭제) = 보수적 — Recording(Line × Casting)이 매달리므로 녹음이 있으면 삭제 차단(설계). 대신 isPublished=false로 내리는 비공개를 우선.
교체 ≠ 삭제. 멀티버전에선 "성우 교체"가 기존 버전 삭제가 아니라 새 Casting 추가 + 기존 비공개로 표현된다. 이력·녹음이 보존된다.

05 관계 · 경계

  • ← Character: characterId로 소속(논리 FK + INDEX). 부모 Character.
  • → Creator: creatorId로 성우 참조(논리 FK + INDEX). 생성 시 creator 존재(활성 CREATOR) 검증.
  • ← Recording: Recording.castingId가 이 버전을 가리킴. casting.characterId == line.characterId 정합 필요.
  • ← EpisodeReview: (회차 × Casting) 단위로 검수 → 통과 시 isPublished.
  • 화면: 배정·발행 관리는 back-office. 성우 본인 캐스팅 조회(creators/me)·연출자 조회(directors/*)는 후속 표면.

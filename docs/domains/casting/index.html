Casting · 캐스팅(성우 버전)

캐릭터에 성우를 배정한 단위. 멀티버전 보이스툰에서 하나의 캐릭터에 붙는 성우 후보 = 버전이다. Character 1:N Casting → Creator. 음성(Recording)의 버전 좌표이자, 검수·발행의 단위.

구현됨 admins/characters/:characterId/castings 멀티버전 Character ↔ Creator
구현 상태. 생성·목록·발행 토글·삭제 구현됨. 삭제는 하드 삭제이며 녹음 존재 가드는 추후(Recording 도메인 대기, §04). isPublished는 현재 관리자 수동 토글(MVP) — 회차×캐스팅 검수(EpisodeCasting) 자동 연동은 추후. 상위 모델은 Playback, 부모는 Character.

01 책임과 특성

  • 버전 = 캐스팅 — 멀티버전(시청자 선택)에서 한 캐릭터의 "성우 A판/B판"이 각각 Casting 한 건. (characterId, creatorId)로 유일.
  • 승자 채택 없음 — 오디션처럼 1명으로 수렴하지 않는다. 발행(isPublished)된 모든 Casting이 시청자 선택지로 제공된다.
  • Recording의 버전 좌표 — 음성은 Recording(Line × Casting). 같은 대사라도 Casting마다 다른 음성·길이를 가진다(타임라인 버전별 해석의 입력).
  • 검수 단위 — EpisodeReview(회차 × 성우)의 "성우"가 곧 이 Casting. 버전별로 검수되고 통과 시 라이브(추후 연동).

03 isPublished — 발행 토글

  • 기본 false — 캐스팅을 만들어도 바로 공개되지 않는다.
  • 현재(MVP): 관리자 수동 토글 — PUT /…/castings/:castingId/publish { isPublished } → casting.changePublish(isPublished).
  • 추후: 검수 연동 — 회차×캐스팅 검수(EpisodeCasting)가 통과하면 자동 발행으로 전환 예정. 그때 발행 입도가 회차별로 내려가면 이 플래그는 EpisodeCasting으로 이동.
  • 재생 선택 — 시청자는 isPublished된 버전 중 캐릭터별로 고른다.

04 라이프사이클 · 삭제

  • 생성(캐스팅 지정) — body는 { creatorId }, characterId는 path. contentId는 character에서 파생. 검증: 캐릭터 존재 · 성우 존재 · (characterId, creatorId) 중복 거부(앱 + DB unique). content는 향후 상태 가드를 위해 함께 로드.
  • 발행/비공개 — changePublish 토글(§03).
  • 해제(삭제) = 하드 삭제(구현됨) — find({id, characterId}) 후 물리 삭제. 녹음 가드는 추후(Recording 생기면 "녹음 있으면 차단"). 일상 변경은 삭제가 아니라 isPublished=false 비공개가 우선이고, 삭제는 "안 쓰는 캐스팅 정리"용.
교체 ≠ 삭제. 멀티버전에선 "성우 교체"가 기존 버전 삭제가 아니라 새 Casting 추가 + 기존 비공개로 표현된다. 이력·녹음이 보존된다.
왜 하드 삭제인가. 소프트 삭제(deletedAt)면 삭제된 행이 (characterId, creatorId) unique 키를 점유해 같은 캐릭터×성우 재캐스팅이 막힌다. 하드 삭제는 키가 풀려 재캐스팅이 가능. 대신 복구·감사는 불가하므로, 실제 보존이 필요한 변경은 비공개(isPublished=false)로 처리한다.

05 관계 · 경계

  • ← Character: characterId로 소속(논리 FK). 부모 Character. contentId는 character에서 파생·비정규화.
  • → Creator: creatorId로 성우 참조(논리 FK). 생성 시 creator 존재 검증(향후 ACTIVE 상태 검증 검토).
  • ← Recording: Recording.castingId가 이 버전을 가리킴. casting.characterId == line.characterId 정합 필요.
  • ← EpisodeReview(추후): (회차 × Casting) 단위 검수 → 통과 시 발행.
  • 화면: 배정·발행 관리는 back-office. 성우 본인 캐스팅 조회(creators/me)·연출자 조회(directors/*)는 후속 표면.

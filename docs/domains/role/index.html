Role · 역할

권한(Permission)의 묶음이자 계정이 참조하는 역할군. 도메인 단위 관리자 역할(계정/콘텐츠/정산/통계/알림)과 SUPER·CREATOR 를 RoleType 으로 구분하며, 역할마다 권한 집합을 부여한다.

구현됨 admins/roles AdminGuard (ADMIN) AR · Role

01 책임과 특성

  • 권한 집합의 단위 — Role 은 Permission 과 N:M(role_permissions 조인). 계정은 Role 을 통해 간접적으로 권한을 가진다.
  • RoleType 1:1 정책 — 같은 type 의 역할은 시스템에 하나만 존재한다(중복 생성 거부). 즉 "콘텐츠 관리자" 역할군은 단일.
  • 권한은 코드로 참조 — 역할 생성/수정 시 permissionCodes(문자열 코드 배열)를 받고, 전부 실재하는 코드인지 검증한다.
  • 수정 = 권한 재할당 — 역할 수정은 이름이 아니라 권한 집합 교체(assignPermissions)를 의미한다.

04 비즈니스 규칙 · 불변식

  • 생성(create) — 동일 type 역할이 이미 있으면 거부("이미 등록된 역할군입니다"). 그래서 RoleType ↔ Role 은 사실상 1:1.
  • 권한 코드 검증 — 입력한 permissionCodes 로 조회한 권한 수가 요청 수와 다르면 "미등록된 권한" 으로 거부(존재하지 않는 코드 차단).
  • 수정(update) — 역할의 권한 집합을 통째로 교체. 존재하지 않는 역할이면 거부.
  • 트랜잭션 — create / update 는 @Transactional() 경계 안에서 처리.

05 라이프사이클

Role 은 상태 enum 이 없다. 라이프사이클은 단순하다:

  • 생성 — RoleType + 이름 + 권한 집합으로 1회 생성(타입 중복 불가).
  • 권한 재할당 — 운영 중 PUT /admins/roles/:id 로 권한 집합을 교체(여러 번 가능).
  • 삭제 없음 — 현재 삭제 엔드포인트는 제공하지 않는다(계정이 참조하므로).

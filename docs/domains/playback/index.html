보이스툰 구성·재생 모델

세로 스크롤 웹툰의 각 컷(Cut)에 성우 대사(Line)·효과음(SoundEffect)·시각효과(CutEffect)를 얹어 재생한다. 한 캐릭터에 여러 성우 버전이 공존하는 멀티버전(시청자 선택)이라, 타이밍은 절대값이 아니라 풀 앵커(anchor) 기반으로 저작하고 버전마다 실제 시간으로 해석(resolve)한다.

설계 멀티버전 full-anchor timing Character · Casting · Episode · Cut Line · Recording · SoundEffect · CutEffect
구현 상태 = 전부 설계. 이 페이지의 도메인(Character / Casting / Episode / Cut / Line / Recording / SoundEffect / CutEffect)은 아직 core-api 모듈로 존재하지 않는다. 서비스 정의를 토대로 합의한 구성·재생 모델을 못 박는 문서이며, 각 도메인 구현 시 별도 상세 페이지로 분리한다. 상위 발행 상태 머신은 Content 참고.

01 서비스 정의

보이스툰 = 세로 스크롤 웹툰의 각 컷 대사에 성우 목소리를 입히고, 컷 단위 시각 효과·비대사 효과음까지 얹어 재생하는 콘텐츠. 한 컷 안에서 일어나는 일은 성격이 다른 세 종류로 나뉜다.

요소성격캐릭터/성우버전검수만드는 화면
Line · 대사텍스트 + 음성 ⭕ 캐릭터, 성우(캐스팅)⭕ 성우별⭕ back-office 등록 → vooth-maker 녹음
SoundEffect · 효과음오디오(에셋) ❌❌ 공용❌ vooth-tool 연출
CutEffect · 시각효과비주얼(흔들림 등) ❌❌ 공용❌ vooth-tool 연출
멀티버전 = (나). 한 캐릭터에 성우 여럿이 녹음하고, 승인된 버전이 모두 발행된다. 시청자는 재생 시 캐릭터별로 들을 성우를 선택한다. 그래서 "최종 1명 채택"으로 수렴하지 않고, 같은 컷의 타임라인이 버전마다 다른 실제 시간으로 펼쳐진다(§03).

02 도메인 맵

Content 아래 형제로 Character·Episode. 캐릭터의 성우 후보는 Casting(= 버전), 음성은 Recording(Line × Casting)으로 버전별로 존재한다.

"성우"는 Casting에서. Content에 성우를 직접 붙이지 않는다. Character → Casting(성우 후보, =버전) → Creator. 검수 단위 EpisodeReview(회차×성우)는 버전(Casting)별로 돌고, 승인된 버전은 isPublished로 라이브가 된다. Line은 characterId로 캐릭터를 참조한다.

03 타이밍 — 풀 앵커 + 버전별 해석

성우마다 같은 대사의 음성 길이가 달라 절대 시간(startAt ms)은 못 쓴다. 모든 요소를 다른 요소(또는 CUT_START)에 앵커로 걸어 한 번만 저작하고, 재생할 버전의 음성 길이를 넣어 실제 시간을 그 자리에서 계산(resolve)한다.

① 한 번만 저작 — 앵커 그래프 (버전 독립)

각 요소는 anchorType·anchorTargetId·anchorEdge(START/END)·offsetMs를 갖는다. 풀 앵커라 대사끼리도 서로 앵커할 수 있다 — 예: Line2를 Line1.END −200으로 걸면 두 대사가 200ms 겹쳐 말한다.

② 버전별 해석 — 같은 저작, 다른 실제 시간

요소 (앵커)성우A Line1=1000 / Line2=800성우B Line1=1300 / Line2=600
Line1 — CUT_START +00 – 10000 – 1300
Line2 — Line1.END +2001200 – 20001500 – 2100
🔊 두둥 — Line1.END +2001200 – 16001500 – 1900
✦ SHAKE — Line2.START −1001100 – 16001400 – 1900
cut hold = max(end)20002100

③ 성우A 해석 결과 (예시)

Line — 캐릭터 대사(음성=버전)
SoundEffect — 효과음
CutEffect — 시각 효과
핵심. 연출자는 앵커로 한 번만 깐다. 버전 전환은 시스템이 음성 길이를 넣어 다시 계산하므로 성우 수만큼 타임라인을 손대지 않는다. 절대 startAt·hold는 저장하지 않는 파생값(버전별 런타임 산출). 앵커 그래프는 비순환(DAG)이어야 한다(검증 필요).
연산 위치. 앵커 해석(resolve)·버전 전환 미리보기·렌더는 vooth-tool(Electron 데스크톱) 클라이언트에서 수행한다 — 데스크톱 리소스를 쓰므로 버전 조합·실시간 계산 비용은 부담이 아니다. core-api는 저작 데이터(앵커·Recording 메타)만 저장·제공하고 절대 시간 계산은 하지 않는다(파생값 미저장과 일관).

04 구성 요소 — 필드 설계

공통 베이스 DddAggregate(id, createdAt/updatedAt/deletedAt, 이벤트)는 생략. 파생값은 클라 입력 금지.

앵커 (timed element 공통 임베드)

필드타입설명
anchorTypeenumCUT_START | LINE | SOUND_EFFECT | CUT_EFFECT — 무엇에 거나
anchorTargetIdnumber · null대상 요소 id(같은 컷 내 soft ref). CUT_START면 null
anchorEdgeenumSTART | END — 대상의 시작/끝 기준(CUT_START는 START)
offsetMsnumber(±)앵커 지점에서의 부호 있는 ms 오프셋

기본값: Line은 직전 Line.END +0(순차), 효과는 CUT_START +0. 검증: 같은 컷·DAG(순환 금지).

Cut — 컷(재생 컨테이너)

필드타입null설명
episodeIdnumber FK✗소속 회차
imageFileIdnumber✗컷 원본 이미지(File). commit-on-attach
imageCropBoxCropBox json✓표시 영역(정규화 0~1). 전체면 null. @vooth/shared
imageWidth / imageHeightnumber(px)✓원본 크기(서버 메타·파생). 스크롤 높이·비율 계산
anchorYnumber(0~1)✓연출: 스크롤 정착 지점(컷 높이 기준 정규화)
gapnumber(px)✓연출: 다음 컷과의 간격
holdOverridenumber(ms)✓버전별 hold(파생)에 +여운. null=연장 없음
ordernumber✗회차 내 정렬

Line — 대사(텍스트) (+앵커)

필드타입null설명
cutIdnumber FK✗소속 컷
characterIdnumber FK✗말하는 캐릭터(참조). 음성 길이는 선택된 Casting에서
texttext✗대사 텍스트(등록=back-office)
ordernumber✗컷 내 대사 순서(편집·기본 앵커 시드)
anchor(4)임베드—위 앵커 필드. 음성 없어도 저작 가능
음성은 Line에 없다. 버전(성우)별로 다르므로 음성은 Recording(Line × Casting)에 있다. Line 재생 길이 = 선택 버전의 채택 Recording 길이.

Casting — 캐릭터 성우 버전 (멀티버전 핵심)

필드타입null설명
characterIdnumber FK✗대상 캐릭터(Character 1:N Casting)
creatorIdnumber FK✗성우. (characterId, creatorId) unique
isPublishedboolean✗이 버전이 라이브인지(검수 승인 후 on). 기본 false
승자 채택 없음. (가) 오디션과 달리 승인된 모든 Casting이 발행된다. 시청자는 재생 시 캐릭터별로 isPublished 버전 중 선택(런타임 매핑; 사전 묶음이 필요하면 후속 CastSet).

Recording — 녹음 테이크 (Line × Casting)

필드타입null설명
lineIdnumber FK✗대상 대사
castingIdnumber FK✗버전(캐릭터×성우). casting.characterId == line.characterId 검증
audioFileIdnumber✗음성(File). commit-on-attach
durationnumber(ms)✓음성 길이(파생). 타임라인 해석 입력
isAdoptedboolean✗같은 (lineId, castingId)의 여러 take 중 사용본. 버전 내 1개 true
recordedAtdatetime✓제출 시각
검수·전이. 검수는 버전(회차×성우)별로 EpisodeReview에서. 첫 Recording 제출 시 이벤트 → Content READY→RECORDING. take 채택(isAdopted)은 연출자(vooth-tool).

SoundEffect — 효과음 (공용·+앵커)

필드타입null설명
cutIdnumber FK✗소속 컷
audioFileIdnumber✗효과음 오디오(File). MVP=컷마다 업로드. commit-on-attach
audioDurationnumber(ms)✓길이(파생)
labelstring✓표시 라벨("두둥!", "솨아아~")
volumenumber(0~1)✓믹싱 음량(기본 1.0)
anchor(4)임베드—대사/CUT_START에 동기화

CutEffect — 시각 효과 (공용·+앵커)

필드타입null설명
cutIdnumber FK✗소속 컷
typeenum✗CutEffectType(SHAKE / ZOOM / FLASH …) — @vooth/shared
paramsjson✓효과별 파라미터(강도·방향·배율). MVP=json+DTO 검증
durationnumber(ms)✗지속(명시). 컷 전체면 CUT_START 앵커 + duration=hold
anchor(4)임베드—대사/CUT_START에 동기화
단위·규칙. ms(정수) = offsetMs / duration / holdOverride / Recording.duration / audioDuration · 정규화 0~1 = anchorY / cropBox / volume · px = gap / imageWidth·Height · commit-on-attach = Cut.imageFileId / Recording.audioFileId / SoundEffect.audioFileId · 저장 안 함(파생) = 절대 startAt · hold · 공유 신규 = CutEffectType(CropBox 재사용).

05 제작 파이프라인

#단계앱산출물Content 상태
1등록back-officeCut(이미지) · Line(text·character·기본 앵커)DRAFT → READY
2캐스팅back-office캐릭터별 Casting 후보 N (멀티버전)—
3녹음vooth-maker버전별 Recording (병렬·부분 진행)READY → RECORDING
4검수vooth-tool버전(회차×성우)별 승인 → isPublishedREVIEWING ↔ APPROVED
5연출/제작vooth-tool앵커 조정(오버랩 포함) · 효과음/시각효과 · take 채택 · hold 여운 · 버전 전환 미리보기 · 렌더(제작)
6발행—예약/발행SCHEDULED → PUBLISHED
연출 게이트. 앵커 저작은 음성 길이 없이도 가능. 미리보기/렌더는 해당 버전 음성이 있을 때 정확하다. "전원 녹음 완료"를 기다리지 않고, 버전이 준비되는 대로 그 버전을 미리보기/발행할 수 있다.

06 확정된 설계 결정

주제결정이유
멀티캐스팅(나) 멀티버전 — 승인된 모든 성우 버전 발행, 시청자가 캐릭터별 음성 선택승자 1명 수렴 안 함. 같은 컷이 버전마다 다른 타임라인
타이밍풀 앵커 — 모든 요소가 CUT_START/다른 요소에 anchor(START/END+offset). 대사끼리 오버랩 가능버전마다 음성 길이가 달라 절대 ms 불가. 동기화·겹말 표현
절대 시간startAt / hold 저장 안 함 — 버전별 런타임 resolve버전 전환 시 자동 재계산. 저작은 1회
캐스팅(B) Casting 엔티티 + isPublished캐릭터 1:N 성우. 버전 = Casting
Recording(Line × Casting), isAdopted로 버전 내 take 선택버전별 음성 + 재녹음 이력
요소 저장Cut/Line/Recording/SoundEffect/CutEffect 독립 AR + 폴리모픽 앵커(soft ref)앱별 쓰기 분산. 앵커는 컷 내 id 참조(앱단 검증)
효과음 에셋(A) 컷마다 업로드 — MVP (audioFileId)MVP 우선. 재사용 라이브러리는 후속
단위시간 ms · anchorY/cropBox/volume 0~1 · gap/이미지 px오디오 동기화는 ms, 레이아웃은 해상도 독립
대안 메모. 풀 앵커는 요소 간 단일 id 공간이 편해 통합 CutElement 테이블(kind 판별)도 후보였으나, 라이프사이클(Line만 캐릭터·녹음 연계)과 타입별 컬럼을 살리려 독립 테이블 + 폴리모픽 앵커를 택했다. 앵커 참조 무결성은 앱 레이어 검증으로 보강한다.

07 화면 경계 (CLAUDE.md)

  • voot-back-office (등록/관리) — Content·Episode·Cut·Character·Casting·Line 텍스트 등록. 연출 UI 없음.
  • vooth-maker (녹음) — 성우가 캐스팅된 캐릭터 Line의 음성(Recording) 녹음 → 검수 요청.
  • vooth-tool (연출/제작) — 앵커·SoundEffect·CutEffect 배치, take 채택, hold 여운, 연속 스크롤·버전 전환 미리보기, 렌더.
  • 데이터 모델은 core-api — cropBox/anchorY/gap/anchor/offsetMs/duration 등은 전부 백엔드 소유.
다음 작업. 멀티버전의 뿌리인 Character + Casting 부터 구현 권장. 이후 Episode → Cut → Line → Recording → (연출) SoundEffect/CutEffect.

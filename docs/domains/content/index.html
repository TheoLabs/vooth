웹툰 콘텐츠의 제작 → 검수 → 발행 라이프사이클. 8개 상태와 화이트리스트 기반 전이로 표현되며, 회차 단위 검수(EpisodeReview)의 롤업과 스케줄러 발행이 자동 전이를 만든다.

구현됨 admins/contents 8-state machine @vooth/shared
구현 상태. Content CRUD + 상태 전이(PUT /admins/contents/:id/status, 수동 allowlist)는 구현됨. 자동 전이(녹음 진입·검수 롤업), expectedPublishOn 스케줄러 발행, EpisodeReview 롤업은 예정. 상태 enum·전이/수동 화이트리스트는 packages/shared/src/content.ts. (옛 마크다운 docs/content-domain-design.md §14는 5상태 버전 — 본 문서/코드가 최신.)

03 전이 표

FromTo트리거조건 / 설명
자동 vs 수동. 수동(주황)은 PUT /admins/contents/:id/status로 사람이 직접 트리거 가능한 전이 — CONTENT_MANUAL_TRANSITIONS / canManualTransitionContent / content.transitionManually. 자동·시스템(파랑)은 녹음 진입·검수 롤업·스케줄러·expectedPublishOn 데이터 전이로, status 엔드포인트로는 거부된다(우회 발행 방지).

04 불변식 · 정책

  • 🔒 PUBLISHED 이후 회귀 없음 — 발행에 도달하면 발행 이전 상태(DRAFT~SCHEDULED)로 가는 경로가 화이트리스트에 없다. ARCHIVED ⇄ PUBLISHED 만 가능.
  • 🔒 status 엔드포인트는 수동 전이만 — 자동·스케줄러·데이터 전이는 canManualTransitionContent로 차단해 우회 발행/녹음 트리거 무력화를 막는다.
  • DRAFT ⇄ READY 는 관리자 수동 — 초안 완료(DRAFT→READY)·초안 회귀(READY→DRAFT)는 status 엔드포인트로 직접 전이. 회귀는 녹음 전(READY)만 가능.
  • 🔒 DRAFT→READY 전제: 녹음 대기 회차 ≥1 — 콘텐츠를 녹음대기(READY)로 올리려면 소속 에피소드 중 최소 1개가 EpisodeStatus.READY여야 한다(0개·전부 DRAFT면 차단). 회차가 anchorY 작업 후 개별 READY로 전환된 뒤에야 콘텐츠를 녹음대기로 올릴 수 있다. cross-aggregate 조건이라 AdminContentService.transitionStatus(앱 계층, nextStatus===READY 가드)에서 episodeRepository.count({ contentId, statuses:[READY] }) > 0 로 검증. 전이 시점 게이트이며 지속 불변식은 아님(이후 회차가 DRAFT로 회귀해도 콘텐츠는 READY 유지).
  • READY → RECORDING 는 자동 — 콘텐츠 소속 에피소드에 성우가 1명이라도 녹음을 진입하면 자동 전이. 이 경로는 역방향 없음(녹음 시작 후엔 READY로 회귀 안 함 — 회귀는 READY→DRAFT만).
  • RECORDING ⇄ REVIEWING 자동 롤업 — 모든 회차 검수 완료 시 REVIEWING, 회차가 검수에서 회귀하면 다시 RECORDING.
  • REVIEWING ⇄ APPROVED 수동 — 검수자가 완료(APPROVED) / 재검수(REVIEWING). status 엔드포인트.
  • APPROVED ⇄ SCHEDULED 는 데이터 전이 — expectedPublishOn 설정 시 SCHEDULED, 해제 시 APPROVED. status 엔드포인트가 아니라 update(필드 설정)로 일어난다.
  • SCHEDULED → PUBLISHED 자동 — 예정일 도달 시 스케줄러가 발행(역방향 없음).

05 구현 현황 · 예정

  • ✅ 상태 전이 엔드포인트 — PUT /admins/contents/:id/status { nextStatus } → content.transitionManually(next) + canManualTransitionContent(수동 allowlist) 검증. 구현됨.
  • ⏳ DRAFT→READY 전제 검증 — 녹음대기 회차 ≥1 게이트(§04). transitionStatus에 nextStatus===READY일 때 episodeRepository.count({ contentId, statuses:[READY] }) 체크 추가. 미구현(설계).
  • ⏳ expectedPublishOn (CalendarDate, nullable) — 설정 시 APPROVED → SCHEDULED, 해제 시 역방향(데이터 전이, update).
  • ⏳ 스케줄러 — expectedPublishOn <= now 인 SCHEDULED 콘텐츠를 PUBLISHED 로 전이(시스템 — transitionTo 사용).
  • ⏳ 자동 전이 — 녹음 진입(READY→RECORDING)·검수 롤업(RECORDING↔REVIEWING)은 EpisodeReview/녹음 연동 시 시스템 전이(transitionTo).
관련. 검수 단위·에피소드 상태(DRAFT/READY/RECORDING/REVIEWING/PUBLISHED)는 별도 EpisodeReview 도메인에서 다룬다. 콘텐츠 상태는 그 회차 검수들의 롤업 결과다.

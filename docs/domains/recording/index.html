Recording · 녹음 테이크

대사(Line)의 버전별 음성. (Line × Casting) 단위이며, 성우가 올린 테이크(take)들 중 하나가 채택(isAdopted)된다. Cut 구성 애그리게이트와 달리 별도 AR — 성우(vooth-maker)가 다른 시점·다른 앱에서 쓰기 때문.

부분 구현 creators/* · directors/* Line × Casting take · 채택 vooth-maker
구현 상태 = 부분 구현. 녹음 화면 조회 · 테이크 업로드 · 채택(select) 구현됨. 삭제(자동 해제 ②) 구현중. 이벤트(RecordingCreatedEvent → EpisodeCasting lazy / Episode READY→RECORDING)는 미배선(§05, 목록류 완료 후). 검토 포인트 A(per-take 검수 미포함)·B(채택=성우 본인)는 결정 완료. 부모 대사·컷은 Cut(Line은 Cut의 child), 버전은 Casting, 타이밍은 Playback 참고.

01 책임과 특성

  • 버전별 음성 — 같은 대사라도 성우(Casting)마다 음성·길이가 다르다. Recording = (Line × Casting). 멀티버전(시청자 선택)의 음성 원천.
  • 테이크 + 채택 — (lineId, castingId)당 여러 테이크(재녹음)를 쌓고, 그중 하나를 isAdopted로 채택. 재생엔 채택 테이크가 쓰인다.
  • 별도 AR인 이유 — Cut/Line/효과는 내부(admin/director)가 쓰지만, 녹음은 성우(vooth-maker)가 다른 시점·다른 앱에서 쓴다. 그래서 Cut 애그리게이트에서 분리.
  • 타임라인 입력 — Line의 재생 길이 = 선택된 버전의 채택 Recording.durationMs. 풀앵커 타이밍의 버전별 해석(Playback)의 핵심 입력.

03 권한 · 검증

  • 캐릭터 정합 — casting.characterId === line.characterId. 엉뚱한 캐릭터 버전에 녹음 금지.
  • 녹음 주체(소유) — creators/*: 현재 성우가 그 casting의 creator일 때만(casting.creatorId === ctx.creator.id) 업로드·삭제 가능. 남의 캐스팅 녹음/수정 금지.
  • 회차 상태 게이트 — 녹음은 EPISODE_RECORDABLE_STATUSES = [READY, RECORDING, REVIEWING]에서만. DRAFT(편집)·APPROVED 이후(잠금)엔 차단. (재녹음은 REVIEWING까지 허용)
  • 채택 주체 — 성우 본인(creators/*). 자기 (lineId, castingId) 테이크 중 하나를 채택. §04 B.

04 검수 · 채택 모델

두 가지를 분리한다 — 채택(어느 테이크를 쓸지) vs 검수(그 버전을 발행할지).

A. per-take 검수 상태 — 결정: 미포함(A1)

  • Recording엔 take + isAdopted + durationMs + audio만. per-take 검수 상태(status/rejectReason) 없음. "어느 테이크가 좋은가"는 isAdopted로 충분.
  • 검수·발행은 EpisodeCasting(회차×캐스팅) 단위. 테이크 개별 검수를 코어에 두면 EpisodeCasting과 이중화되므로 안 둔다. (테이크 단위 반려가 실제로 필요해지면 append-only enum으로 확장.)

B. 누가 채택(isAdopted)하나? 결정: B1(성우 본인)

  • 성우 본인이 자기 테이크 중 하나를 채택(creators/*). vooth-tool mock의 selectedTakeByCreator(creator→recordingId)와 일치. 직관적(자기 베스트 제출).
  • 검수/발행은 별도 — 채택은 "어느 테이크를 쓸지"일 뿐, 그 버전을 발행할지는 EpisodeCasting(연출/검수자)이 정한다. 연출자가 테이크를 고르는 B2는 채택 안 함.
층위 정리. ① 채택(Recording.isAdopted) = (line×casting)당 쓸 테이크 1개 · ② 검수·발행(EpisodeCasting) = 그 회차 버전을 시청자에게 노출할지(현재 Casting.isPublished 수동 MVP). 재생엔 발행된 EpisodeCasting의 채택 테이크가 쓰인다.

05 이벤트 · 회차 상태 연동

  • 첫 녹음 → EpisodeCasting lazy 생성 + 회차 전이 — Recording 생성 시 RecordingCreatedEvent(lineId·castingId·episodeId 포함) 발행 → (a) EpisodeCasting(episodeId, castingId) 없으면 RECORDING으로 upsert(멱등), (b) 회차 첫 녹음이면 Episode READY→RECORDING 자동 전이. episodeId 비정규화 덕에 둘 다 판정 쉬움.
  • 녹음 완료 → 검수 — 회차의 모든 (라인×발행대상 캐스팅)에 채택 테이크가 차면 그 EpisodeCasting이 REVIEWING으로. 롤업 판정은 EpisodeCasting 단위 — MVP에선 directors 수동 전이로.
  • 채택/삭제 정리 — Episode 하드 삭제 시 EpisodeRemovedEvent → Recording @EventHandler가 그 회차 녹음 일괄 삭제(논리 FK라 EDA, episodeId 멱등). Cut 정리와 동형. S3 오디오 정리도 동반(추후).

06 라이프사이클 · 삭제

  • 생성(테이크 업로드) — creator. presign→S3 PUT→POST 시 라인↔회차 정합 + 캐릭터 정합/소유 + recordable 게이트 검증 → commit(audio/) + durationMs 저장. take는 (lineId, castingId)의 max(take)+1 자동. 테이크 ≤3.
  • 채택(select) — creator 본인. 소유 + recordable 게이트 → isAdopted 토글, 같은 (lineId, castingId) 형제 자동 해제(자기 자신 제외 → 재채택 멱등).
  • 삭제 — 본인 테이크, recordable 상태에서만. 하드 삭제(테이크라 부담 없음, S3 정리 추후). 정책 = 자동 해제(②): 채택된 테이크를 지우면 그 라인은 채택 0개가 된다(남은 테이크로 자동 재채택하지 않음 — 성우가 다시 선택). 회차 잠금(APPROVED↑) 후엔 차단.

08 관계 · 경계

  • → Line(Cut의 child): lineId 논리 참조. Line은 Cut 애그리게이트 내부 — 참조만(수정은 Cut 루트).
  • → Casting: castingId 논리 FK. 버전·성우 정체성. casting.creatorId로 소유 검증.
  • → Episode: episodeId 논리 FK(비정규화). 회차 상태 게이트·롤업·EDA 정리의 키.
  • → File: audioFileId로 음성 참조(commit-on-attach, audio/).
  • ← EpisodeCasting: 회차×캐스팅 검수·발행이 채택 Recording을 기준으로 라이브 판단. RecordingCreatedEvent로 lazy 생성. 현재는 Casting.isPublished 수동 MVP.

Composition · 구성·재생

Recording · 녹음 테이크

대사(Line)의 버전별 음성. (Line × Casting) 단위이며, 성우가 올린 테이크(take)들 중 하나가 채택(isAdopted)된다. Cut 구성 애그리게이트와 달리 별도 AR — 성우(vooth-maker)가 다른 시점·다른 앱에서 쓰기 때문.

설계 (검토용) creators/* · directors/* Line × Casting take · 채택 vooth-maker
구현 상태 = 설계(검토 대기). Recording은 아직 core-api 모듈로 존재하지 않는다. 이 문서는 구현 전 합의용 설계안이며, §04 검토 포인트의 결정이 끝나면 구현에 들어간다. 선행(Casting·Line·Episode READY 전이)은 모두 구현됨. 부모 대사·컷은 Cut(Line은 Cut의 child), 버전은 Casting, 타이밍은 Playback 참고.

01 책임과 특성

  • 버전별 음성 — 같은 대사라도 성우(Casting)마다 음성·길이가 다르다. Recording = (Line × Casting). 멀티버전(시청자 선택)의 음성 원천.
  • 테이크 + 채택 — (lineId, castingId)당 여러 테이크(재녹음)를 쌓고, 그중 하나를 isAdopted로 채택. 재생엔 채택 테이크가 쓰인다.
  • 별도 AR인 이유 — Cut/Line/효과는 내부(admin/director)가 쓰지만, 녹음은 성우(vooth-maker)가 다른 시점·다른 앱에서 쓴다. 그래서 Cut 애그리게이트에서 분리.
  • 타임라인 입력 — Line의 재생 길이 = 선택된 버전의 채택 Recording.durationMs. 풀앵커 타이밍의 버전별 해석(Playback)의 핵심 입력.

03 권한 · 검증

  • 캐릭터 정합 — casting.characterId === line.characterId. 엉뚱한 캐릭터 버전에 녹음 금지.
  • 녹음 주체(소유) — creators/*: 현재 성우가 그 casting의 creator일 때만(casting.creatorId === ctx.creator.id) 업로드·삭제 가능. 남의 캐스팅 녹음/수정 금지.
  • 회차 상태 게이트 — 녹음은 EPISODE_RECORDABLE_STATUSES = [READY, RECORDING, REVIEWING]에서만. DRAFT(편집)·APPROVED 이후(잠금)엔 차단. (재녹음은 REVIEWING까지 허용)
  • 채택 주체 — (검토 포인트 B) §04 참고. 잠정: 성우 본인이 자기 테이크 중 채택(selectedTakeByCreator 모델과 일치).

04 검수 · 채택 모델 검토 포인트

두 가지가 헷갈리기 쉬워 분리해 둔다 — 채택(어느 테이크를 쓸지) vs 검수(그 버전을 발행할지).

A. per-take 검수 상태를 넣을까?

  • 옵션 A1 (MVP·추천) — Recording엔 take + isAdopted + durationMs + audio만. per-take 검수 상태 없음. "어느 테이크가 좋은가"는 isAdopted로 충분. 발행 여부(검수)는 캐스팅 단위로 따로(EpisodeCasting, 추후 / 현재 Casting.isPublished 수동 MVP).
  • 옵션 A2 — vooth-maker mock처럼 status(RECORDED→REVIEWING→APPROVED/REJECTED) + rejectReason을 테이크마다. 테이크 단위 반려/재녹음 흐름을 코어에 둠. 비용: 상태 머신 + 검수 surface가 EpisodeCasting과 이중화될 수 있음.
  • 판단: MVP는 A1. 테이크 단위 반려가 실제로 필요해지면 A2로 확장(append-only enum). ← 검토 요망

B. 누가 채택(isAdopted)하나?

  • 옵션 B1 (추천) — 성우 본인이 자기 테이크 중 하나를 채택. vooth-tool mock의 selectedTakeByCreator(creator→recordingId)와 일치. 직관적(자기 베스트 제출). 검수/발행은 별도(EpisodeCasting).
  • 옵션 B2 — 연출자(directors)가 테이크 중 선정. 내부가 품질을 통제. 다만 멀티버전이라 캐스팅마다 골라줘야 해 작업량↑.
  • 판단: B1(성우 자기선택) + 발행 게이트는 EpisodeCasting. ← 검토 요망
층위 정리. ① 채택(Recording.isAdopted) = (line×casting)당 쓸 테이크 1개 · ② 발행(Casting.isPublished / 추후 EpisodeCasting) = 그 버전을 시청자에게 노출할지. 재생엔 발행된 캐스팅의 채택 테이크가 쓰인다. 검수=캐스팅(회차×캐스팅) 단위라 테이크 개별 검수는 기본 안 둔다(A1).

05 이벤트 · 회차 상태 연동

  • 첫 제출 → 회차 전이 — 회차에 첫 Recording이 생기면 RecordingCreatedEvent 발행 → Episode READY→RECORDING 자동 전이(EDA, 멱등). 라인별이 아니라 회차 첫 녹음 기준(episodeId 비정규화 덕에 판정 쉬움).
  • 녹음 완료 → 검수 — 회차의 모든 (라인×발행대상 캐스팅)에 채택 테이크가 차면 RECORDING→REVIEWING. 이 롤업 판정은 EpisodeCasting(추후) 단위가 정확 — MVP에선 directors 수동 전이(PUT directors/…/status)로.
  • 채택/삭제 정리 — Episode 하드 삭제 시 EpisodeRemovedEvent → Recording @EventHandler가 그 회차 녹음 일괄 삭제(논리 FK라 EDA, episodeId 멱등). Cut 정리와 동형. S3 오디오 정리도 동반(추후).

06 라이프사이클 · 삭제

  • 생성(테이크 업로드) — creator. presign→S3 PUT→POST 시 commit(audio/) + durationMs 저장. take는 (lineId, castingId)의 max(take)+1 자동.
  • 채택 — (검토 B) creator 본인. isAdopted 토글(형제 자동 해제). 회차 recordable 상태에서만.
  • 삭제 — 본인 테이크. 채택 테이크 삭제는 채택 해제 후/차단 검토. 회차 잠금(APPROVED↑) 후엔 차단.

08 관계 · 경계

  • → Line(Cut의 child): lineId 논리 참조. Line은 Cut 애그리게이트 내부 — 참조만(수정은 Cut 루트).
  • → Casting: castingId 논리 FK. 버전·성우 정체성. casting.creatorId로 소유 검증.
  • → Episode: episodeId 논리 FK(비정규화). 회차 상태 게이트·롤업·EDA 정리의 키.
  • → File: audioFileId로 음성 참조(commit-on-attach, audio/).
  • ← EpisodeCasting(추후): 회차×캐스팅 검수·발행이 채택 Recording을 기준으로 라이브 판단. 현재는 Casting.isPublished 수동 MVP.

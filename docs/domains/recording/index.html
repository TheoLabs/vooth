Recording · 녹음 테이크

대사(Line)의 버전별 음성. (Line × Casting) 단위이며, 성우가 올린 테이크(take)들 중 하나가 채택(isAdopted)된다. Cut 구성 애그리게이트와 달리 별도 AR — 성우(maker)가 다른 시점에 쓰기 때문.

설계 creators/* · directors/* Line × Casting take · 채택
구현 상태 = 설계. Recording은 아직 core-api 모듈로 존재하지 않는다. 부모 대사·컷은 Cut(Line은 Cut의 child), 버전은 Casting, 타이밍은 Playback 참고.

01 책임과 특성

  • 버전별 음성 — 같은 대사라도 성우(Casting)마다 음성·길이가 다르다. Recording = (Line × Casting).
  • 테이크 + 채택 — (lineId, castingId)당 여러 테이크(재녹음)를 쌓고, 연출자가 그중 하나를 isAdopted로 채택. 재생엔 채택 테이크가 쓰인다.
  • 별도 AR인 이유 — Cut/Line/효과는 내부(admin/director)가 쓰지만, 녹음은 성우(maker)가 다른 시점·다른 앱에서 쓴다. 그래서 Cut 애그리게이트에서 분리.
  • 타임라인 입력 — Line의 재생 길이 = 선택된 버전의 채택 Recording.duration. 버전별 해석(Playback)의 핵심 입력.

02 애그리게이트 — Recording

공통 베이스 DddAggregate(id, createdAt/updatedAt/deletedAt, 이벤트)는 생략.

필드타입null설명
lineIdnumber✗대상 대사(Cut의 child Line). 논리 FK + INDEX
castingIdnumber✗버전(Character×Creator). 논리 FK + INDEX. casting.characterId === line.characterId 정합
audioFileIdnumber✗음성(File). commit-on-attach(audio/)
durationnumber(ms)✗음성 길이. 클라(maker) 제공(S3 HEAD로 못 구함)
isAdoptedboolean✗같은 (lineId, castingId) 테이크 중 사용본. 기본 false
테이크 & 채택. (lineId, castingId)당 여러 행(테이크) 허용. isAdopted=true는 그 쌍에서 최대 1개 — 부분 unique라 DB로 못 박고 앱에서 보장(채택 시 형제 false). INDEX (lineId, castingId). 녹음 주체는 casting.creatorId로 파생(별도 컬럼 없음).

03 권한 · 검증

  • 정합 — casting.characterId === line.characterId(엉뚱한 캐릭터 버전에 녹음 금지).
  • 녹음 주체 — creators/*: 현재 성우가 그 casting의 creator일 때만(casting.creatorId === ctx.creator.id) 업로드 가능. 남의 캐스팅 녹음 금지.
  • 채택 — directors/*(연출자, ADMIN): 테이크 중 하나를 isAdopted 처리(형제 자동 해제).

04 이벤트 · 상태 연동

  • 첫 제출 → 회차 전이 — 라인에 첫 Recording이 제출되면 RecordingSubmittedEvent 발행 → Episode READY→RECORDING 자동 전이 트리거(추후 배선).
  • 검수·발행 — (회차 × Casting) 검수(EpisodeCasting, 추후)가 통과하면 그 버전이 발행. Recording 개별이 아니라 캐스팅 단위로 검수된다.

05 라이프사이클 · 삭제

  • 생성(테이크 업로드) — maker. presign→S3 PUT→POST 시 commit(audio/) + duration 저장.
  • 채택 — directors. isAdopted 토글(형제 해제).
  • 삭제 — 테이크 삭제. 채택/검수된 테이크는 차단 검토(추후 EpisodeCasting 연동).

06 API 표면 (멀티 앱) (예정)

네임스페이스. 생성·내 조회·삭제=creators/*(CreatorGuard), 채택·검수 조회=directors/*(DirectorGuard=ADMIN). 컷 구성(Cut/Line/효과)은 별도 — Cut.

07 관계 · 경계

  • → Line(Cut의 child): lineId 논리 참조. Line은 Cut 애그리게이트 내부 엔티티 — 참조만(수정은 Cut 루트).
  • → Casting: castingId 논리 FK. 버전·성우 정체성.
  • → File: audioFileId로 음성 참조(commit-on-attach).
  • ← EpisodeCasting(추후): 회차×캐스팅 검수·발행이 채택 Recording을 기준으로 라이브 판단.

EpisodeCasting · 회차×캐스팅

(회차 × 성우 버전)의 검수·발행 단위. Episode × Casting의 조인이며, 멀티버전 발행·중간 하차/이어받기·필모 정밀도·회차 상태 롤업이 모두 이 단위로 정리된다. 음성(Recording)의 회차 묶음이자, 시청자에게 노출되는 버전 선택지의 출처.

설계 (검토용) directors/* · public Episode × Casting 검수·발행 단위 lazy 생성
구현 상태 = 설계(검토 대기). EpisodeCasting은 아직 core-api 모듈로 존재하지 않는다. 현재 발행은 Casting.isPublished 수동 토글(MVP)로 대체 중이며, 이 도메인은 그 발행/검수를 회차 단위로 정밀화하는 후속 단계다. 부모는 Episode·Casting, 음성은 Recording, 재생은 Playback.

01 책임과 특성

  • 검수·발행 단위 — "이 회차에서 이 캐스팅(버전)을 검수하고 발행한다". Recording(테이크)·Casting(버전 정체성)과 달리, 발행 여부가 정해지는 곳.
  • 멀티버전 발행 — 한 회차에 발행된 EpisodeCasting이 여럿(버전마다 1개). 시청자는 캐릭터별로 그중 선택. "승자 1명 채택" 아님.
  • 중간 하차/이어받기 — 캐릭터 1명에 1~5화는 캐스팅 A의 EpisodeCasting, 6화+는 캐스팅 B의 EpisodeCasting. 회차 단위로 버전이 바뀐다(하차 정책 = 이어받기).
  • 상위 롤업의 입력 — Episode.status·Casting.status는 사실 이 EpisodeCasting들의 롤업이다. 필모("이 성우 1~5화 담당")도 PUBLISHED EpisodeCasting 집합으로 정밀하게 나온다.

03 상태 — EpisodeCastingStatus

RECORDING → REVIEWING → APPROVED → PUBLISHED
                ↑__________|   (REJECTED = 반려·재녹음)
  • RECORDING — 이 회차 이 버전 녹음 진행(라인별 채택 진행 중).
  • REVIEWING — 대상 라인 모두 채택 완료 → 검수 요청.
  • APPROVED / REJECTED — 검수 통과 / 반려(재녹음).
  • PUBLISHED — 발행(시청자 노출). publishedAt 기록.
  • 하차는 Casting 레벨 — 중간 하차 시 미래 회차엔 그 캐스팅의 EpisodeCasting을 안 만들면 됨. 이미 PUBLISHED된 과거 회차는 그대로 유지(필모 보존).

05 생성 시점 · 이벤트 결정: lazy

  • 생성 = lazy(첫 녹음) — (episodeId, castingId)의 첫 Recording 제출 시 RecordingCreatedEvent(episodeId·castingId 포함) → EpisodeCasting 없으면 RECORDING으로 upsert. @Unique(episodeId, castingId)라 멱등. (대안 ①: 회차 READY 시 등장 캐스팅 일괄 프로비저닝 — 늦은 배정/이어받기를 위해 back-fill 트리거가 추가로 필요해 채택 안 함.)
  • 왜 lazy인가 — 트리거 1개(RecordingCreated)로 단순하고, 이어받기·중간 하차·늦은 캐스팅 배정을 특별처리 없이 흡수. 안 나오는 캐릭터/안 녹음한 버전은 행이 안 생김(phantom 없음).
  • 예정(분모)은 파생 — "이 회차에 녹음해야 할 버전 집합"(진행률·검수 보드 분모)은 EpisodeCasting이 아니라 Casting(등장 캐릭터)에서 계산. 검수 보드의 "미시작" 표시는 예정 LEFT JOIN EpisodeCasting(실적)으로 머지한다.
  • 이벤트 — EpisodeCastingPublishedEvent → (a) Casting.status 롤업(→PUBLISHED), (b) 필모 프로젝션 갱신, (c) Episode.status 롤업, (d) 구매 가능 버전 갱신(추후). 회차 삭제 시 EpisodeRemovedEvent → EpisodeCasting EDA 정리(episodeId 멱등).

07 관계 · 경계

  • → Episode: episodeId 논리 FK. 1:N(회차 → 등장 캐스팅들).
  • → Casting: castingId 논리 FK. 1:N(캐스팅 → 참여 회차들). 발행 롤업으로 Casting.status 결정.
  • groups Recording: 같은 episodeId + castingId의 채택 음성 묶음이 검수 대상.
  • ← Purchase(추후): 구매가 (회차 × 캐스팅) 버전을 참조 — "이 회차를 어느 성우로 살지".

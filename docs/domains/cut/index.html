Composition · 구성·재생

Cut · 컷 (구성 애그리게이트)

회차(Episode) 본문의 한 컷 = 세로 스크롤 패널 이미지 + 재생 타임라인 컨테이너이자, 대사(Line)·효과음(SoundEffect)·시각효과(CutEffect)를 owned child로 품는 애그리게이트 루트다. 음성(Recording)만 별도 AR로 분리된다.

구현됨 admins/episodes/:episodeId/cuts · admins/cuts/:cutId/lines 애그리게이트 루트 Line owned
구현 상태. Cut(create/list/update/remove) + Line(create/update/remove) 구현됨. SoundEffect/CutEffect, 연출 편집(anchor·anchorY/gap/holdOverride, directors), 컷 구성 일괄 조회는 설계. 음성은 별도 AR Recording. 타이밍·앵커 모델은 Playback, 부모는 Episode 참고.

01 책임과 특성

  • 세로 스크롤 패널 — 컷은 회차를 구성하는 이미지 한 장. order 순으로 세로로 쌓여 읽힌다.
  • 타임라인 컨테이너 + 구성 루트 — 컷이 활성(dwell)되는 동안 자기 안의 Line/SoundEffect/CutEffect가 앵커 타임라인 위에서 재생된다. 세 요소는 컷의 owned child.
  • 왜 한 애그리게이트인가 — ① 등록(텍스트·이미지)과 연출(앵커·효과)이 내부 주체(admin/director)의 같은 단위 작업, ② 앵커 그래프가 컷 내부 관계라 한 경계 안에서 불변식 검증이 깔끔.
  • Recording만 분리 — 음성은 성우(maker)가 다른 시점에 쓰므로 별도 AR. 컷을 건드리지 않는다.

04 애그리게이트 · 영속성

  • 루트만 AR — Cut extends DddAggregate(이벤트 보유). 자식은 extends DddBaseAggregate(감사 컬럼/헬퍼만, 이벤트 없음).
  • owned 관계 — Cut @OneToMany(cascade: true, orphanedRowAction: 'delete') + 자식 @ManyToOne(() => Cut, { onDelete: 'CASCADE' }). 애그리게이트 내부라 물리 FK가 맞다(논리 FK는 cross-aggregate에만). 현재 lines만 구현(soundEffects/cutEffects는 추후).
  • CutRepository 하나 — save(cut)가 자식 insert/update/삭제(orphan)까지 cascade. 조회는 relations: { lines: true }.
  • 변경은 루트 통해 — Line 추가/수정/삭제 모두 "Cut 로드 → 도메인 메서드(cut.addLine/updateLine/removeLine) → save". 도메인 메서드가 컷 내 order 중복·존재 등 인트라 불변식 검증.
  • 서비스 분리 — 컷 본체=AdminCutService, 대사=AdminLineService. 둘 다 CutRepository(루트) 경유라 애그리게이트 경계 유지.
코드베이스 첫 owned-child 패턴. 다른 도메인은 전부 flat AR(논리 FK)인데, Cut만 내부 자식 + cascade + 물리 FK. 앵커 그래프 응집·등록/연출 단위 일치를 위한 의도적 예외.

05 앵커 — intra-aggregate

  • 앵커는 Line의 anchorMetadata(json)에 저장. targetId가 같은 컷 안 형제를 가리키므로 검증을 Cut 루트에서 한다(cross-AR soft ref 불필요).
  • 현재 AnchorType.LINE만 — 등록(admins/*)은 anchor를 받지 않아 항상 null(순차 기본)로 생성. 연출(directors)에서 대사 동기화·오버랩으로 설정(추후). SoundEffect/CutEffect 생기면 요소 간 cross-element 앵커 + DAG·same-cut 검증 강화.
  • 해석(resolve)·버전 전환·렌더는 클라(vooth-tool, Electron). core-api는 앵커·요소 데이터만 저장(절대 시간·hold는 파생, 미저장). Playback §03.

06 라이프사이클 · 삭제

  • Cut 생성/수정/삭제(admins) — episode DRAFT일 때만(구조 편집 게이팅). 생성/이미지교체 시 commit('image/'), order 중복 거부.
  • Line 생성/수정/삭제(admins, AdminLineService) — Cut 루트 경유 + episode DRAFT 게이팅 + character 존재 검증. 삭제는 orphanedRowAction:'delete'로 실제 DELETE.
  • Episode 삭제 시 EDA 정리(구현) — Episode가 하드 삭제되며 EpisodeRemovedEvent 발행 → Cut의 @EventHandler가 그 회차의 컷을 일괄 삭제(컷→라인은 물리 FK cascade). cross-aggregate(Episode↔Cut 논리 FK)라 DB cascade 대신 이벤트로 정리. 멱등(episodeId 기준).
  • 대사 anchorY 설정(Line 발화 세로 위치) — directors, 녹음 전(DRAFT 게이트). 회차 단위 벌크(DirectorLineService.setAnchorY, Cut 루트 경유). 구현됨
  • 연출 편집(타임라인 anchor·Cut gap/holdOverride, SoundEffect/CutEffect) — directors, 녹음 이후. 설계.
  • Recording 가드 — Line 삭제 시 그 라인의 녹음(별도 AR)이 고아가 되므로, Recording 생기면 녹음 있으면 차단 추가 예정. (현재는 Episode를 DRAFT일 때만 삭제 → 녹음 없어 안전)

08 관계 · 경계

  • ← Episode: episodeId 논리 FK(cross-aggregate).
  • ↓ owned: Line(구현)/SoundEffect/CutEffect(설계) — 물리 FK + cascade, intra-aggregate.
  • Line → Character: characterId 논리 FK. character↔content 정합은 FE 책임(단순 존재검증).
  • ← Recording: Recording(별도 AR)이 lineId로 Line(자식)을 논리 참조. 성우 녹음.
  • → File: 컷 이미지·효과음 오디오를 fileId로 참조, 읽을 때 URL 유도(getPublicUrl).

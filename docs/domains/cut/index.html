Composition · 구성·재생

Cut · 컷 (구성 애그리게이트)

회차(Episode) 본문의 한 컷 = 세로 스크롤 패널 이미지 + 재생 타임라인 컨테이너이자, 대사(Line)·효과음(SoundEffect)·시각효과(CutEffect)를 owned child로 품는 애그리게이트 루트다. 음성(Recording)만 별도 AR로 분리된다.

설계 admins · directors / …/cuts 애그리게이트 루트 Line · SoundEffect · CutEffect owned
구현 상태 = 설계. Cut은 아직 core-api 모듈로 존재하지 않는다. 핵심 모델 결정: Cut이 Line/SoundEffect/CutEffect를 owned child로 갖는 컴포지션 애그리게이트이고, Recording만 별도 AR이다(성우가 쓰므로). 타이밍·앵커 해석은 Playback, 부모는 Episode, 음성은 Recording 참고.

01 책임과 특성

  • 세로 스크롤 패널 — 컷은 회차를 구성하는 이미지 한 장. order 순으로 세로로 쌓여 읽힌다.
  • 타임라인 컨테이너 + 구성 루트 — 컷이 활성(dwell)되는 동안 자기 안의 Line/SoundEffect/CutEffect가 앵커 타임라인 위에서 재생된다. 세 요소는 컷의 owned child.
  • 왜 한 애그리게이트인가 — ① 등록(텍스트·이미지)과 연출(앵커·효과)이 내부 주체(admin/director)의 같은 단위 작업, ② 앵커 그래프가 컷 내부 관계라 한 경계 안에서 불변식(DAG·same-cut) 검증이 깔끔.
  • Recording만 분리 — 음성은 성우(maker)가 다른 시점에 쓰므로 별도 AR. 컷을 건드리지 않는다.

04 애그리게이트 · 영속성

  • 루트만 AR — Cut extends DddAggregate. Line/SoundEffect/CutEffect는 plain @Entity child. 이벤트는 Cut 루트에서 발행.
  • owned 관계 — @OneToMany(cascade: true, orphanedRowAction: 'delete') + 물리 FK cutId(ON DELETE CASCADE). 애그리게이트 내부라 물리 FK가 맞다(논리 FK는 cross-aggregate에만).
  • CutRepository 하나 — save(cut)가 자식 insert/update/삭제(orphan)까지 cascade. 조회는 relations: { lines, soundEffects, cutEffects }.
  • 변경은 루트 통해 — Line 추가/SFX 배치/앵커 설정 모두 "Cut 로드 → 루트 메서드로 변경 → save". 요소별 독립 repo·모듈 없음.
  • 읽기는 우회 가능 — maker의 "녹음할 라인 조회"는 Line read-model로 직접 쿼리(루트 우회 OK).
코드베이스 첫 owned-child 패턴. 다른 도메인은 전부 flat AR(논리 FK)인데, Cut만 내부 자식 + cascade + 물리 FK를 쓴다. 앵커 그래프 응집과 등록/연출 단위 일치를 위한 의도적 예외.

05 앵커 — intra-aggregate

  • 요소들의 anchorTargetId가 같은 컷 안 형제를 가리키므로, DAG·순환·same-cut 검증을 Cut 루트에서 한 번에 한다(cross-AR soft ref 불필요).
  • 등록 직후: 앵커는 순차 기본(Line은 직전 Line.END). 연출(directors)에서 대사 동기화·오버랩으로 조정.
  • 해석(resolve)·버전 전환·렌더는 클라(vooth-tool, Electron). core-api는 앵커·요소 데이터만 저장(절대 시간·hold는 파생, 미저장). Playback §03.

06 라이프사이클 · 삭제

  • 생성 — admins. episode 존재 검증 + episode가 DRAFT일 때만(구조 편집 게이팅) + order 중복 거부 + 이미지 commit. 연출 값·요소는 이후 채움.
  • 수정 — 등록(이미지/순서/Line 텍스트)=admins, 연출(SFX/FX/anchor/anchorY/gap/hold/cropBox)=directors. 구조 편집은 episode DRAFT 한정(연출 편집 게이팅은 추후 분리 검토).
  • 삭제 — episode DRAFT일 때만. Cut 삭제 시 자식(Line/SFX/FX)은 cascade로 함께 삭제(애그리게이트 내부). 단 Recording은 별도 AR이라 lineId 참조가 남으므로 녹음 있으면 차단(추후 Recording 연동).

07 API 표면 — 루트 경유

입도는 granular하되 서비스는 Cut 애그리게이트를 로드→변경→저장. 등록=admins/*, 연출=directors/*(DirectorGuard=ADMIN).

표면예시 엔드포인트주체
컷 생성/목록/수정/삭제admins/episodes/:episodeId/cuts (목록은 order순 전체)back-office
Line 추가/수정/삭제(텍스트)admins/cuts/:cutId/linesback-office
SoundEffect/CutEffect 배치, 앵커·연출 설정directors/cuts/:cutId/...vooth-tool
컷 구성 조회(미리보기·렌더)directors/...(컷+요소 일괄)vooth-tool
참고. 위 엔드포인트는 전부 CutRepository(루트)를 통해 자식을 변경한다. Recording은 별도 도메인(creators/* 생성 · directors/* 채택).

08 관계 · 경계

  • ← Episode: episodeId 논리 FK(cross-aggregate).
  • ↓ owned: Line/SoundEffect/CutEffect (물리 FK + cascade, intra-aggregate).
  • Line → Character: characterId 논리 FK. character↔content 정합은 FE 책임(단순 존재검증).
  • ← Recording: Recording(별도 AR)이 lineId로 Line(자식)을 논리 참조. 성우 녹음.
  • → File: 컷 이미지·효과음 오디오를 fileId로 참조, 읽을 때 URL 유도.

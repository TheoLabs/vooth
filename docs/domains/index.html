core-api 도메인 문서

NestJS 백엔드(apps/core-api)의 도메인별 책임·비즈니스 규칙·라이프사이클을 정리한 문서입니다. 각 도메인은 DDD 레이어(domain / application / infrastructure / presentation)로 구성되며, 코드(apps/core-api/src/modules, packages/shared)를 source of truth로 작성했습니다.

읽는 법. 각 도메인 카드를 누르면 상세 문서로 이동합니다. 구현됨 은 core-api 모듈로 존재하는 도메인, 설계 는 문서/공유 enum 으로 확정됐지만 모듈화 전인 도메인입니다.

Identity & Access · RBAC

관리자/크리에이터 계정과 역할·권한(RBAC), 로그인을 담당하는 바운디드 컨텍스트. 모든 표면은 admins/* 네임스페이스.

Account

구현됨
admins/accounts

계정 애그리게이트. 가입 승인·역할 변경·탈퇴 상태 머신과 ADMIN/CREATOR 구분.

상태 머신승인 정책RBAC 주체

Role

구현됨
admins/roles

역할군(RoleType) 1:1 + 권한(Permission) N:M. 역할당 권한 집합을 정의·수정.

RoleType 유일성권한 묶음

Permission

구현됨
admins/permissions

권한 카탈로그(코드 PK). 카테고리별 read-only 시드 데이터. 역할이 참조.

카탈로그읽기 전용

Auth

구현됨
admins/auth

Google 로그인(웹 idToken / 데스크톱 PKCE) + JWT 발급, 최초 로그인 시 계정 자동 생성.

Google OAuthJWTauto-provisioning

Production · 제작

녹음에 참여하는 성우(크리에이터)의 제작 도메인. 계정 승인 시 이벤트로 생성되며 캐스팅·녹음·정산의 참조 중심.

Creator

구현됨
creators/me · admins/creators

성우 프로필. Account 1:1, AccountActivedEvent 로 멱등 생성, 삭제 없는 영속 레코드. creators/me 조회·수정(commit-on-attach).

이벤트 생성Account 1:1no-delete

Content · 발행

웹툰 콘텐츠의 제작·검수·발행 라이프사이클. 상세 도메인 설계는 docs/content-domain-design.md 참고.

Content

설계
admins/contents

콘텐츠 발행 상태 머신(8상태). 녹음→검수→승인→예약→발행→보관 전이와 불변식.

8-state machine검수 롤업스케줄 발행

Tag

구현됨
admins/tags

콘텐츠 분류 태그 마스터. CRUD + 자유 문자열 color. usageCount는 이벤트 재계산(Content 대기).

전역 태그 풀hard deleteusageCount 파생

Platform · 공용

여러 도메인이 공유하는 인프라성 도메인. presigned 업로드 파일을 관리한다.

구현됨
admins/files

presigned 업로드 파일 메타. commit-on-attach 정책, fileId 참조 + 읽기 시 URL 유도.

commit-on-attachS3 presign키만 저장

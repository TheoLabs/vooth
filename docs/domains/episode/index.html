Composition · 구성·재생

Episode · 회차

작품(Content)의 한 회차(chapter). Cut의 부모이자 연재·검수·구매의 단위다. 회차별로 발행되고(expectedPublishOn 스케줄러), 구매도 회차 단위로 일어난다.

구현됨 admins/contents/:contentId/episodes Content 소속 7-state machine
구현 상태. 생성·목록·상세·수정·삭제 구현됨(admins). 삭제는 하드 삭제 + EDA(EpisodeRemovedEvent → Cut 정리). directors: 목록(cutCount/lineCount, title 검색)·상세·상태 전이(DRAFT↔READY, 되돌리기 포함) 구현됨. 공유 enum은 packages/shared/src/episode.ts. 상위 구성·재생 모델은 Playback, 발행 상위는 Content 참고.

01 책임과 특성

  • 연재 단위 — 작품은 회차로 나뉘어 순차 발행된다. Content 1:N Episode, (contentId, chapter)로 회차 번호 유일.
  • Cut의 부모 — 회차 본문은 컷들로 구성. Episode 1:N Cut → Cut이 Line/SoundEffect/CutEffect를 담는다(Playback).
  • 구매 단위 — 시청자는 회차를 구매하며, 캐릭터별 성우 버전을 고른다. 구매 가능한 성우는 회차×캐스팅 검수완료 기준(EpisodeCasting, 추후).
  • 등장 캐릭터는 파생 — 회차에 등장하는 캐릭터는 Line.characterId에서 도출한다(별도 저장 안 함).

05 전이 표 · 불변식

FromTo트리거조건 / 설명
  • 🔒 PUBLISHED는 종착 — 발행 이후 발행 이전 상태로 가는 경로는 화이트리스트에 없다.
  • 검수 완료 ↔ 발행 대기 분리 — APPROVED(품질 OK)와 PUBLISHED(실제 공개) 사이에 SCHEDULED(예정일 대기)를 둔다. APPROVED↔SCHEDULED는 expectedPublishOn 설정/해제.
  • 녹음 허용 상태 — EPISODE_RECORDABLE_STATUSES = [READY, RECORDING, REVIEWING]. 검수 중에도 재녹음 가능(필수). APPROVED 이후 재녹음은 재검수(→REVIEWING→RECORDING)를 거친다.
  • 멀티버전 롤업 — 이 status는 사실상 (회차 × 캐스팅) 진행의 롤업. 자동 전이(READY→RECORDING, REVIEWING→APPROVED 등) 배선은 녹음/EpisodeCasting 연동 시 연결(현재 enum·화이트리스트만 확정).

06 발행 — expectedPublishOn 스케줄러

  • expectedPublishOn(CalendarDate, YYYY-MM-DD HH:mm:ss)에 예정 발행 일시를 둔다. 생성 시 null, 수정으로 설정. 설정 시 APPROVED → SCHEDULED(해제 시 역방향).
  • 스케줄러가 expectedPublishOn ≤ now인 SCHEDULED 회차를 SCHEDULED → PUBLISHED로 자동 전이.
  • Content의 발행도 회차 발행들의 롤업으로 이어진다(Content 상태 머신).
왜 CalendarDate(문자열)인가. Content의 expectedPublishOn과 동일 타입·정책. 타임존 해석은 표시 측 책임이며, 저장은 ISO 문자열(@vooth/shared CalendarDate).

07 라이프사이클 · 삭제

  • 생성 — back-office. content 존재 검증 + (contentId, chapter) 중복 거부(앱 + DB unique). 썸네일 있으면 commit(image/). isFree는 chapter에서 자동, status=DRAFT.
  • 목록·상세 — content-scoped(contentId). 상세는 { id, contentId } 정합 조회. 서버 기본 정렬 없음(프론트가 sort/order 지정) — 의도.
  • 수정(구현) — 정보 수정(title/isFree/expectedPublishOn/thumbnail, 변경 필드만). 구조 게이팅(validateChildEditable) 안 함 — Episode 자체 정보는 DRAFT 이후에도 수정 가능(자식 Cut/Line 편집만 DRAFT 한정).
  • 삭제(구현) — 하드 삭제. soft delete는 (contentId, chapter) unique를 점유해 재등록을 막으므로 불가. DRAFT일 때만(Episode.remove() 검증). Episode.remove()가 EpisodeRemovedEvent를 발행 → repo가 아웃박스 적재 + 하드삭제 → Cut @EventHandler가 속한 컷을 EDA로 정리(컷→라인은 물리 FK cascade). DRAFT라 녹음 등 다운스트림 참조가 없어 안전.
  • 상태 전이(directors, PUT :episodeId/status) — transitionTo+canTransitionEpisode 검증, DTO가 타깃을 @IsIn([DRAFT, READY])로 제한. DRAFT↔READY: 앵커 작업 완료 → 녹음 진입(DRAFT→READY), 녹음 전 재편집 되돌리기(READY→DRAFT). 구현됨

08 관계 · 경계

  • ← Content: contentId로 소속(논리 FK). Content.status는 회차 상태들의 롤업.
  • → Cut: Episode 1:N Cut. 회차 본문 컷. Playback.
  • ↔ Casting(추후 EpisodeCasting): (회차 × 캐스팅) 단위로 녹음·검수·발행 상태. 회차별 구매 가능 성우의 근거.
  • 화면: 등록·관리 back-office(admins/contents/:contentId/episodes). maker(녹음)·tool(연출)·시청자(구매)는 조회.
